# M4 و M5 — موضوع/پیشینهٔ نسخه‌دار و فرم‌ساز پویا (راهنمای کوتاه)

## M4: موضوع پایان‌نامه
- **مسیر:** صفحهٔ پرونده → کارت «نسخه‌های موضوع پایان‌نامه».
- **دانشجو:** «ثبت نسخهٔ جدید» → عنوان فارسی/انگلیسی، کلیدواژه، توضیح → «ذخیره پیش‌نویس» یا «ارسال برای بررسی».
- **استاد راهنما:** نسخهٔ `در انتظار بررسی استاد راهنما` → «تأیید استاد راهنما» یا «درخواست اصلاح»/«رد» (**دلیل اجباری، حداقل ۵ نویسه**).
- **مدیر گروه / تحصیلات تکمیلی:** نسخهٔ `در انتظار تأیید گروه` → «تأیید گروه» (مجوز `cases.approve_topic_group`).
- **تغییر موضوع:** پس از تأیید، دکمه به «درخواست تغییر موضوع» تغییر می‌کند و **دلیل اجباری** است. تغییر تا وضعیتی مجاز است که در تنظیمات `topic.changeAllowedUntil` تعیین شده (پیش‌فرض `approved`). با `topic.requireFileOnChange` فایل هم اجباری می‌شود (شناسهٔ فایل از بخش فایل‌های پرونده).
- **قواعد:** هر اصلاح یک نسخهٔ **جدید** می‌سازد؛ تاریخچه بازنویسی یا حذف نمی‌شود؛ در هر پرونده حداکثر **یک نسخهٔ فعال** وجود دارد (ایندکس یکتای جزئی + سوئیچ در همان تراکنش)؛ ستون‌های قدیمی `thesis_cases.title_fa/title_en/keywords` همیشه آینهٔ نسخهٔ فعال‌اند تا جستجو/گزارش/PDF دادهٔ کهنه نخوانند.
- **گردش‌کار:** تأییدها در صورت وجود تعریف «چرخهٔ کامل» پرونده را از `workflow_transitions` جلو می‌برند (WAITING_SUPERVISOR → SUPERVISOR_APPROVED → GROUP_REVIEW → TOPIC_APPROVED).

## M4: پیشینه پژوهش
- **دور (round)** = یک چرخهٔ ارسال/بررسی؛ در هر دور می‌توان چند **نسخه** ثبت کرد.
- ارسال: خلاصه (حداقل ۵۰ نویسه)، اهداف، شکاف پژوهشی، کلیدواژه، تعداد منابع (حداقل از `literature.minReferences`) و فایل اختیاری.
- بررسی: تأیید / درخواست اصلاح / رد — دو مورد آخر **دلیل اجباری** دارند. تأیید، دور را می‌بندد؛ اصلاح، دور را برای ارسال نسخهٔ بعدی باز نگه می‌دارد.

## M5: فرم‌ساز پویا
- **پنل مدیر:** `/admin/forms` (مجوز `forms.view` برای مشاهده، `forms.manage` برای ساخت/ویرایش/انتشار).
- «فرم جدید» → کد فرم (لاتین کوچک، مثل `proposal`)، عنوان، افزودن/حذف/جابه‌جایی فیلد، نوع فیلد، اجباری‌بودن، گزینه‌ها، شرط نمایش ساده (`visibleWhen`: مثلاً فقط وقتی `has_advisor = دارد`).
- **پیش‌نمایش زنده** دقیقاً همان چیزی است که دانشجو می‌بیند (همان payload، همان اعتبارسنجی).
- **انتشار:** نسخهٔ منتشرشده **تغییرناپذیر** است. برای تغییر، «ساخت نسخهٔ جدید» و پس از ویرایش، «انتشار». پاسخ‌های قبلی به نسخهٔ خودشان گره خورده‌اند و هرگز بازنویسی نمی‌شوند.
- **فرم پیش‌فرض پروپوزال:** `npm run db:seed-forms` نسخهٔ ۱ را با ۱۶ فیلد استاندارد (عنوان فارسی/انگلیسی، بیان مسئله، اهمیت، اهداف، پرسش‌ها، فرضیه‌ها، روش، جامعه/نمونه، ابزار، تحلیل، منابع، کلیدواژه، نوع پژوهش و مشاور شرطی) منتشر می‌کند. اجرای دوباره آن بی‌اثر است (idempotent) و ویرایش‌های مدیر را بازنویسی نمی‌کند.
- **فرم دانشجو:** کارت «پروپوزال (فرم پویا)» در صفحهٔ پرونده، رندرشده از تعریف منتشرشده؛ «ذخیرهٔ پیش‌نویس» و «ارسال برای بررسی»؛ خطاهای اعتبارسنجی با برچسب فارسی همان فیلد برگردانده می‌شوند.

## تنظیمات مرتبط
| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `topic.changeAllowedUntil` | `approved` | آخرین وضعیتی که تغییر موضوع تا آن مجاز است |
| `topic.requireFileOnChange` | `false` | اجباری‌بودن فایل هنگام تغییر موضوع |
| `literature.minReferences` | `15` | حداقل تعداد منابع پیشینه |
| `notify.reminderDay1AfterDays` / `notify.reminderDay3AfterDays` | `1` / `3` | آستانه‌های یادآوری |
| `notify.escalationAfterDays` / `notify.escalationRole` | `5` / `grad_office` | آستانه و نقش مقصد ارتقا |
| `notify.termControlRole` | `grad_office` | گیرندهٔ هشدار کنترل ترم |
