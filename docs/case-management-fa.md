# مدیریت پرونده پایان‌نامه — شمال‌داک

## مفهوم پرونده

هر دانشجوی تحصیلات تکمیلی در صورت احراز شرایط، یک پرونده پایان‌نامه با شماره یکتا دارد. شماره پرونده با فرمت زیر تولید می‌شود:

```
TH-{سال_شمسی}-{شماره_مسلسل}
```

مثال: `TH-1405-00001`

شماره‌گذاری از طریق PostgreSQL Sequence انجام می‌شود و در شرایط هم‌زمانی کاملاً ایمن است.

## فیلدهای اصلی پرونده

| فیلد | توضیح | الزامی |
|---|---|---|
| `caseNumber` | شماره یکتای پرونده | خودکار |
| `studentFullName` | نام دانشجو | بله |
| `studentNumber` | شماره دانشجویی | اختیاری |
| `studentUserId` | ارتباط با حساب کاربری | اختیاری |
| `department` | گروه آموزشی | اختیاری |
| `degreeLevel` | مقطع تحصیلی | پیش‌فرض: کارشناسی ارشد |
| `fieldOfStudy` | رشته | اختیاری |
| `academicYear` | سال تحصیلی | اختیاری |
| `titleFa` | عنوان فارسی | اختیاری (الزامی قبل از ارسال) |
| `titleEn` | عنوان انگلیسی | اختیاری |
| `abstractFa` / `abstractEn` | چکیده | اختیاری |
| `keywords` | کلمات کلیدی | اختیاری |
| `currentStatus` | وضعیت جاری | خودکار |
| `createdBy` / `updatedBy` | کاربر ایجاد/ویرایش‌کننده | خودکار |

## نقش‌ها و مجوزها

### دانشجو
- مشاهده پرونده خود (`cases.view_own`)
- ایجاد پرونده (`cases.create`)
- ویرایش پیش‌نویس (`cases.update_own_draft`)
- ثبت موضوع (`cases.submit_topic`)
- بارگذاری و دانلود فایل (`cases.files.upload`, `cases.files.download`)

### استاد راهنما / مشاور
- مشاهده پرونده‌های ارجاع‌شده (`cases.view_assigned`)
- بررسی موضوع (`cases.review_topic`)
- انتساب استادان (`cases.assign_supervisors`)
- تغییر وضعیت (`cases.transition_status`)
- دانلود فایل (`cases.files.download`)

### مدیر گروه
- مشاهده پرونده‌های گروه (`cases.view_department`)
- ایجاد پرونده (`cases.create`)
- بررسی موضوع و تغییر وضعیت
- انتساب استادان

### تحصیلات تکمیلی / مدیر سیستم
- مشاهده همه پرونده‌ها (`cases.view_all`)
- تمام عملیات مجاز

## قواعد ایجاد و ویرایش

- پرونده فقط توسط کاربر دارای مجوز `cases.create` ایجاد می‌شود.
- ویرایش اطلاعات فقط در وضعیت `draft` یا `revision_required` مجاز است.
- پرونده‌های `rejected` و `archived` قابل ویرایش نیستند.
- هر تغییر با ثبت رویداد و Audit Log همراه است.

## تاریخچه پرونده

تاریخچه پرونده از جدول `thesis_case_events` خوانده می‌شود و در صفحه جزئیات به‌صورت Timeline نمایش داده می‌شود. هر رویداد شامل:
- نوع رویداد
- وضعیت قبلی و جدید
- کاربر اجراکننده
- توضیح
- دلیل (در صورت وجود)
- زمان ثبت

## سیاست آرشیو

- آرشیو فقط از وضعیت‌های `approved` یا `rejected` مجاز است.
- پرونده آرشیو‌شده دیگر قابل ویرایش یا تغییر وضعیت نیست.
- تاریخچه پرونده پس از آرشیو حفظ می‌شود.
- حذف فیزیکی پرونده انجام نمی‌شود.
